## Screens / components

### Enrollment page — fresh state

- **Route:** `GET user/two-factor` (name `two-factor.settings`, new; authenticated)
- **Components:** `auth/two-factor-settings.blade.php` inside the authenticated app shell → `x-ui.page-header` (title "Two-factor authentication"), 3-step indicator (start/scan/confirm — presentational), `x-ui.card` with the QR (`<img src="{{ route('two-factor.qr-code') }}">` per 005-D04) + manual key fallback, `x-ui.field` for the 6-digit code (monospace, centered), `x-ui.button` confirm → POST `two-factor.confirm`. Validation-error state per mockup.
- **Mockup section:** `#s-enroll-fresh`.

### Enrollment page — setup-mode state

- Same view, additional `x-ui.banner` (brass): "Restricted session — only this page is available until setup completes." Confirm button copy: "Confirm and continue". On success the flag clears and the user lands in the app without re-signing-in.
- **Mockup section:** `#s-enroll-setup`.

### Enrollment page — active state

- **Components:** status row (active dot + confirmed date), `x-ui.button` secondary "Regenerate recovery codes" → POST regenerate (shows the new set once, per the recovery-codes screen), `x-ui.button` secondary "Turn off two-factor" → password-confirmation gate then DELETE (existing `confirmPassword` behavior).
- **Mockup section:** `#s-enroll-done`.

### Recovery codes — once display

- Rendered as part of the enrollment page immediately after a successful confirm (or regeneration): `x-ui.banner` (brass, "Shown once"), monospace code grid, "I've saved them — continue" button. Never rendered on later visits.
- **Mockup section:** `#s-codes`.

### Challenge page

- **Route:** `GET two-factor-challenge` (name `two-factor.login`, new; guest-with-challenge-session only, else redirect to login)
- **Components:** `auth/two-factor-challenge.blade.php` inside the public/guest layout → `x-ui.card` with the account email shown (not editable), `x-ui.field` code input, `x-ui.button` "Verify and sign in" → POST `two-factor.login.store`; divider; recovery-code form → same endpoint with `recovery_code`. Generic error state per mockup (one message for all failures).
- **Mockup sections:** `#s-challenge`.
