## Screens / components

### Admin invitations page

- **Route:** `GET admin/invitations` (name `admin.invitations.index`, existing)
- **Components:** `admin/invitations/index.blade.php` inside the authenticated app shell → `x-ui.page-header` (title "Team invitations" + "Invite someone" action), `x-ui.banner` (mail-not-configured notice; one-time accept-link banner), `x-ui.card` wrapping the create form (`x-ui.field` email, `x-ui.select` role + matter scope, `x-ui.button` submit), `x-ui.table` for the invitation rows with `x-ui.status` badges (Pending/Accepted/Revoked/Expired) and `x-ui.chip` role labels, `x-ui.modal` for revoke confirmation (danger + consequence line), `x-ui.empty` for the no-invitations state, `x-ui.toast` on create/revoke.
- **Roles rendered:** org_admin sees the full page. Non-admins never reach it (existing `RequireOrgAdmin` denial).
- **Mockup section:** `#s-admin` (table, form, banners, empty state, validation-error state, revoke modal).
- **Approved deviations from mockup:** none (TBD at build).

### Invitation accept page — valid token

- **Route:** `GET /invitations/{token}` (name `invitations.show`, existing; guest middleware)
- **Components:** `invitations/show.blade.php` inside the public/guest layout → `x-ui.card` (org name, `x-ui.chip` role, matter-scope line, expiry note), `x-ui.field` (name, password; email locked/disabled), `x-ui.button` ("Create account & accept"), link to sign-in with return to the token URL.
- **Mockup section:** `#s-accept-ok`.
- **Approved deviations from mockup:** none (TBD at build).

### Invitation accept page — invalid token

- **Route:** same; all four failure states (unknown/expired/revoked/accepted) render one identical page.
- **Components:** `x-ui.empty` ("This invitation link doesn't work") + secondary button back to sign in.
- **Mockup section:** `#s-accept-bad`.
- **Approved deviations from mockup:** none (TBD at build).

## States

- **Empty:** "No invitations yet" with the Invite action (admin table).
- **Loading:** N/A — server-rendered pages; no async loading states introduced.
- **Validation:** inline `x-ui.field` errors on the create form (bad email/role); accept form reuses the register/login validation already built.
- **Denied:** non-admin on admin routes → existing denial semantics; cross-org invitation access → 404.
- **Conflict:** N/A.
- **Success:** one-time accept-link banner (copy button) after creation; toast on revoke; welcome toast + redirect home after accept.
- **Destructive:** revoke uses `x-ui.modal` with the danger button + plain-language consequence line ("Revoking cancels the accept link immediately… This cannot be undone").

## Data volume & layouts

- **Realistic volume:** table shows 5 rows covering all four statuses + matter-scoped row; fixtures include the cross-org adversarial case (never rendered).
- **Desktop layout:** 1120px max-width content; create form in a two-column grid; table scrolls inside its card below 760px.
- **390 px layout:** single column; buttons full-width; table horizontal-scrolls within its card; modal fits the viewport.

## Accessibility

- Keyboard-navigable; visible focus; status badges pair color with text labels (never color-only).
- All timestamps absolute; timezone is the viewer's.
- Target: WCAG 2.1 AA on new surfaces.

## What this spec does NOT cover

Backend behavior lives in `03-contract.md`; invitation business rules live in spec 001. This spec covers presentation only.
