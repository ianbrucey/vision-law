# Spec 010 — App home & authenticated shell (2026-10-15)

**Branch:** `feat/010-app-home` · **Brief:** APPROVED 2026-10-15 (merged `ad37eee`)

Ian's first login exposed the gap this spec closes: the app had no home,
no navigation, and no sign-out control anywhere — spec 002 built the shell
as a frame whose nav/org/userMenu slots no page ever furnished, and
003-D02 had deferred the app home to its own spec. Spec 010 furnishes the
frame.

## What shipped

- `GET /home` (route `app.home`) + `HomeController` + `home.blade.php`:
  dashboard v1 from existing data only — my matters (006 `accessibleBy`
  scope, most recently updated first, count, link to index), recent
  activity (the 006 audit read model aggregated over the same scope),
  role-appropriate quick actions, and a security status card (2FA
  confirmed state, enabled passkey count, link to the security page).
  Zero-matter organizations get one guided empty state; no placeholders.
- Chrome as the layout default: `layouts/app` now renders `<x-app.nav>`
  and `<x-app.user-menu>` whenever a page doesn't furnish the slots (page
  slots still win). Sign out (Fortify POST, unchanged) is reachable from
  the top-bar user menu and from the mobile drawer.
- The public landing header is auth-aware (C-07): signed-in visitors see
  "Open app" + Sign out; guests see exactly the 003 page.
- Fixtures: `specs/010-app-home/04-fixtures.json` is the canonical graph;
  `FixtureLoader::loadHomeFixtures()` extends the 006 runner with
  `two_factor`, `passkey`, and `audit_event` types (audit rows go through
  `AuditLogger` at stepped test-now offsets so ordering is deterministic).

## Two findings worth remembering

- **JSON-only surfaces (001-D06) keep colliding with UI briefs.** The
  sessions API and the document-search API have no pages, so C-05's
  "Sessions" menu entry and "Document search" nav entry were omitted as
  documented deviations (010-D02, 010-D09) rather than shipped as links
  that dump JSON. Both entries return when the pages exist.
- **Adding `GET /home` moves Laravel's guest redirect.**
  `RedirectIfAuthenticated::defaultRedirectUri()` resolves to a route
  named — or pathed — `dashboard`/`home`, so C-01 alone flipped the
  003-pinned "signed-in users on /login land on `/`". The behavior is
  contractual (003-D02 / O-01), so it's now pinned explicitly:
  `RedirectIfAuthenticated::redirectUsing(fn () => '/')` in
  `FortifyServiceProvider` (010-D10), with the route named `app.home` as
  defense in depth.

Also: the host's stale **route cache** (from the domain cutover) made
`RegistrationFlagTest` fail on the host at baseline while CI was green —
cache state, not code. Cleared before the runs; CI remains the authority.
